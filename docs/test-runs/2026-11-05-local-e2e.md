# Local end-to-end run, 2026-11-05

A new teammate's run of the whole app on a Mac, from a fresh clone of `main` at `c5c3eaa`.
It was done by hand, before the `make e2e` browser suite (#82) was merged.
Nothing was reused from another checkout: the venv, the model, and the index were all built fresh.

## How it was run

1. `git reset --hard origin/main`, then `make setup`, with each step timed.
2. The CI checks: `make test`, and in `ui/`, `npm run lint`, `npm run typecheck`, and `npm run build`.
3. The demo, the way `make demo` runs it, on port 8001 because 8000 was in use: `cd api && HF_HUB_OFFLINE=1 WSC_AUDIT_PATH=<temp>/log.jsonl ../.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8001`.
4. A walk of the demo in a browser, with wifi on, reading every network request.
5. `trust.verify` on the temp audit log.

## Bugs

### 1. The showcase text was stale (fixed on `main` by #84)

At `c5c3eaa`, `/showcase/` said the wikiHow lists were the default and listed `EOCC-SSDG-*` files.
The default is ddg, and ddg refuses SSDG questions.
The rebuilt showcase in #84 uses the SSDG question only as the refusal example.

### 2. The example chips show SSDG questions until `/api/health` answers (still on `main`)

Steps to reproduce:

1. Start the demo on a busy machine and open `/`.
2. For the first 1 to 3 s, the chips and the input placeholder read "low lube oil pressure on number two SSDG".
3. Click that chip before the health check answers.

The question is refused, because a DDG-51 has no diesel generators.
The fallback list is `EXAMPLES` in `ui/components/symptom-input.tsx`.
A fix could use the ddg examples as the fallback, or hide the chips until the health check answers.

### 3. `make verify` ignores `WSC_AUDIT_PATH` (still on `main`)

Steps to reproduce:

1. Run the demo with `WSC_AUDIT_PATH=/tmp/x/log.jsonl` and make a few entries.
2. Run `WSC_AUDIT_PATH=/tmp/x/log.jsonl make verify`.

It runs `trust.verify ../audit/log.jsonl` and prints "OK: chain intact, 0 entries", although that file does not exist.
The log at `/tmp/x/log.jsonl` is never checked.
There are two causes: the Makefile passes a fixed path, and the verifier reports a missing log as intact.
`cd api && ../.venv/bin/python -m trust.verify /tmp/x/log.jsonl` checks the right file.
